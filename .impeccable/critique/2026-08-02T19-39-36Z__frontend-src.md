## Design Specificity Verdict

**Partially authored for this product — the top layer is category-interchangeable.** Craft below the surface is genuine and specific: 30px mono countdown with progress fill, direction chips, score bar as the core unit of meaning, C++/AI dual signal path, tabular-nums mono numerics, dark mission-control palette. Those decisions could only be made for a monitoring desk. But the vocabulary is the generic 2024 admin kit (OKLCH indigo, mono eyebrows, 6px cards, pill chips, "TC" monogram); strip the crypto nouns and this is a CI/CD dashboard. Missed product character: no chart thumbnail in the dashboard rows (the product's most distinctive artifact is one click deep), the hero signal event renders as an empty panel most days, and the "trading desk" personality is ornamental rather than structural.

**Deterministic scan**: detect.mjs CLI reported 8 findings (exit 2, all warnings): layout-transition ×4 (AppSidebar 139/323, ScoreBar 57, DashboardView 290), side-tab ×3 (DashboardView 260, EngineView 230, StrategyView 113), bounce-easing ×1 (tokens.css:77). Of these, most are inert: bounce-easing is a dead token (zero usages of var(--spring)); side-tab ×2 lack border-radius so the pattern doesn't apply; ScoreBar/DashboardView width animations are canonical progress fills. Real hit: AppSidebar.vue:139 desktop width-collapse transition and DashboardView.vue:260 scan-bar. The browser overlay found far more substantive issues the CLI missed: low-contrast ×9+ (3.4:1 buttons), undersized-ui-text ~40+ elements (9.5/10.5px), tiny-text (11px), flat-type-hierarchy (1.5–1.9:1), dark-glow, pulsing-dot, gpt-thin-border-wide-shadow on login.

**Visual overlays**: Injection succeeded — a user-visible overlay (markers + top banner) rendered in the [Human] tab. Console reported per page: login 9 anti-patterns (run 1) / 6 (run 2, lazy-contrast timing variance), dashboard 20, settings 35, signals 48.

## Overall Impression

A disciplined, coherent system with genuine craft at the token level, undermined by three systemic facts: the threshold the UI quotes is fiction (three conflicting numbers), the contrast floor fails on both themes, and the dashboard's headline numbers actively misrepresent a healthy system (all-zero stat row with 386 real analyses in the DB). The single biggest opportunity: make the signal event — the product's reason to exist — the visual hero instead of an empty panel.

## What's Working

1. **Token-system discipline**: 132 OKLCH variables, coherent dark+light theming, :focus-visible rings, prefers-reduced-motion support, tabular-nums mono numerics — rare coherence for a solo-built dashboard.
2. **Scan control design**: the scan-bar (30px mono countdown + gradient progress + Pause/Run-now) is a true hero element, correctly duplicated in the sidebar foot so control is one click away on any page.
3. **Detail-page hierarchy**: screenshot as visual anchor, side info panel, reasoning beneath — the correct reading order for reviewing a signal.

## Priority Issues

**[P0] Threshold truth is three different numbers.** Dashboard card meta + empty state say "score ≥ 7.0", app/routes/dashboard.py:66 filters ≥8.0, configured NOTIFICATION_THRESHOLD is 3.0 (live). Traders calibrate against fiction; ScoreBar's green/amber/red bands at 7/5 are likewise disconnected — a signal-grade 3.0–4.9 score renders red.
- Why it matters: the quality bar users trust is wrong; a trader acting on the UI number acts on fiction.
- Fix: derive all threshold copy from the settings endpoint; never hard-code in DashboardView.vue, the backend, or ScoreBar.
- Suggested command: $impeccable clarify

**[P0] System-wide contrast failures (computed from actual tokens).** Dark: muted-2 on bg = 2.3:1 (placeholders, footnotes, timestamps), primary-button white on indigo = 3.4:1, card borders = 1.24:1. Light theme worse: LONG/SHORT/status chips 1.6–2.4:1. Every 10.5px mono label rides on these.
- Why it matters: WCAG AA failures on the most common reading surfaces; worst for Sam (low vision, screen reader).
- Fix: lift muted-2 to ≥4.5:1 in both themes; darken indigo accent-fg pairing; deepen green-soft/red-soft/amber-soft chip text in light theme.
- Suggested command: $impeccable audit

**[P1] Notifications page renders raw Telegram HTML.** Live rows show literal `🤖 <b>C++ Trigger: LONG</b> | @64580.04 | …` markup.
- Why it matters: visible markup is an integrity failure on an audit surface.
- Fix: strip tags server-side when storing, or sanitize before render.
- Suggested command: $impeccable harden

**[P1] Destructive/operational actions under-guarded.** Engine Start/Stop, Pause loop (sidebar), Delete are single-click; Delete uses native confirm() while BaseModal sits unused; sidebar poll can silently overwrite user's pause state.
- Why it matters: one misclick silences the entire monitoring loop or destroys history with no consequence preview.
- Fix: modal confirmation with consequence summary for engine stop and delete; distinct color for "Pause loop" vs "Run scan now"; reconcile the 8s syncRun poll with optimistic UI.
- Suggested command: $impeccable harden

**[P2] Hero metrics misrepresent the system.** avg_score/analyses_today are today-scoped, so the headline row shows "0.0"/"0" on a quiet day while Recent analyses below shows 5.0s — dashboard reads dead when healthy. Countdown/progress freeze in 15s steps (empty 1s setInterval is dead code; useCountdown composable unused).
- Why it matters: the emotional peak of the product (a signal) renders as an empty panel; the daily rhythm viewers rely on is frozen.
- Fix: label stats "today", show "—" when no data, add overall average; wire the 1s countdown tick.
- Suggested command: $impeccable clarify / $impeccable polish

## Persona Red Flags

**Alex (Power User)**: Export CSV is a disabled corpse (data pipeline blocked); screenshots need click → /analysis/:id → wait — no thumbnails in lists; filters reset on every navigation; countdown freezes 15s; his primary metric (recent signals) is an empty panel.

**Sam (Accessibility)**: computed contrast failures (light chips 1.6:1, dark muted-2 2.3:1); Settings subnav items are `<a>` without href — not focusable, invisible to keyboard/SR (live-verified); 10.5px all-caps labels; score level is color-only (double-encoding present for direction, not for score); native confirm() breaks SR predictability.

**Jordan (First-Timer)**: login tells him "Default: admin/admin123" which fails; username prefilled "admin" guarantees a failing first submit; 7 nav items with overlapping concepts (Recent analyses / Recent signals / History / Signals); "C++ Engine", "VolR", "BW" unexplained.

## Minor Observations

- Topbar user chip hard-codes "david@local"/"DA" regardless of JWT subject.
- Breadcrumbs are static text, not links.
- Engine page: "STOPPED" twice; log panel "PAUSED" while stopped; signal table drops leading zero (.0078).
- ScoreBar renders NEUTRAL 0.0 rows red — noise across History.
- History date inputs show "0" before any pick.
- link-btn actions lack aria-labels and visual priority.
- BaseModal lacks focus trapping and return-focus management.
- Empty setInterval in DashboardView is dead code; useCountdown.ts orphaned.
- Detector: pulsing-dot (6×6 infinite pulse in sidebar foot), dark-glow zero-offset on every page, overused-font (inter 33–70%), gpt-thin-border-wide-shadow on login form — mostly polish-level.

## Questions to Consider

1. The product's highest-value event (a signal above threshold) renders as an empty panel while the biggest type on the dashboard is a stat row that says "0.0" — whose information design prioritizes emptiness over the thing the system exists to deliver?
2. There are three different definitions of "a signal" in this codebase (UI copy 7.0, backend filter 8.0, configured threshold 3.0). Where is the single source of truth, and would a trader who acted on the number they were shown be acting on reality?
3. If every crypto noun were removed (BTCUSDT, LONG/SHORT, VolR), the remaining surface would be a competent server monitor — is that generality a success, and which one change would make it unambiguously a *trading* desk rather than a dashboard?
